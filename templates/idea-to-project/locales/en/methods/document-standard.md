# Document Standard

## When to persist

Explanations, questions and unsettled discussion may stay in conversation. Update project material only when goals, scope, design or actions change, or evidence is worth revisiting. Update an existing topic section first; discussion count, agent actions and another review are not reasons for a new file.

## Granularity and format

- A simple topic needs one file, without a mandatory directory, index.md and overall-plan.md pair. Keep small conclusions and decisions in the existing topic with reasons and necessary sources.
- Before creating a file, explain in the response who needs to use it separately, for which task, and why an existing section is insufficient. Do not create an approval checklist. Reproducible experiments, caller-facing interfaces and separately accepted deliverables can qualify; a different reader or another discussion alone does not.
- Add module directories and indexes only after multiple independently useful artifacts exist. The main document links requirements, decisions and evidence. Improve entry links before relocating stage directories.
- Short records need a title, conclusion or table, relevant boundaries and sources. Durable designs add updated date, status, scope and sections; important decisions record confirmation date, reasons, alternatives and impact; evidence records method, results, limitations and reproduction conditions.
- Do not mandate five sections, duplicate summaries, version numbers or an edit log for every change. Reserve versions/change records for milestones, external versions or material changes. Distinguish facts, inferences and hypotheses; use relative Markdown links.
- Name files by stable object and purpose, not supplement, final, latest or routine version suffixes. Do not merge everything into a giant document.

## Reading entry

Start from the [workspace home](../workspace/index.md) and retrieve progressively. The home may contain about five lines of progress and reading guidance, dated and linked to authoritative sources; it is a summary, not a second status ledger. Child indexes use one-line entries, status and updated date without duplicating body content.

After material changes check the nearest index and its parent reachability. Without a child index, link directly from the existing parent. Default navigation shows Current or still-open material; historical access follows the [freshness standard](./artifact-freshness-standard.md).
