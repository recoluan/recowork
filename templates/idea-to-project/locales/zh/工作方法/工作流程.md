# 从想法到落地工作流程

> 版本：1.0
> 状态：当前有效

## 结论在前

这是一个工作流、两个阶段、一个工作空间。先判断用户当前是否还在探索方向；只有用户明确确认方向并选择进入项目后，才将探索结论转化为项目推进的输入。索引用于导航，方向决策包与项目简报分别承载阶段性的当前事实。

## 阶段一：探索与验证

1. 读取 `工作空间/index.md`、`01-探索与验证/index.md`、根目录 `待确认问题.md`，按需读取专题索引。
2. 澄清问题、用户、场景、约束、成功信号、已知事实与未知项。
3. 发散多个方向；每个方向记录价值、关键假设、风险、反证和最小验证。
4. 将可推翻的假设放入验证；不以更多脑暴代替证据。
5. 更新 `01-探索与验证/方向决策包.md`：候选方向、证据、未选方向、关键风险、建议和下一步。
6. 停下并请用户明确选择：继续探索、先验证关键假设，或确认以指定方向进入项目。

## 阶段门：确认进入项目

只有用户明确确认后才进入项目阶段。确认记录应包含：选定方向、为什么现在进入项目、仍接受的风险、首个范围与成功标准。未选方向保留为历史或待验证材料，不删除理由。

## 阶段二：项目推进

1. 将确认的方向决策包作为 `项目简报.md` 的输入，补齐目标、范围、非目标、约束和成功标准。
2. 若项目约定仍有实质缺口，先更新 `待确认问题.md` 并等待确认。
3. 在确认范围内进入 `02-需求与约束/`、`03-方案设计/`、`04-计划与决策/`、`05-过程留痕/`、`06-评审验证/`。
4. 对每项重要工作按计划、实施、验证、权威记录回写和索引更新推进。
5. 执行 [质量门禁](./质量门禁.md) 与 [产物保鲜规范](./产物保鲜规范.md)：将当前结论原地收口，列出归档候选并等待确认，再说明结果、风险和下一步。
