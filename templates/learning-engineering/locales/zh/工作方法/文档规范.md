# 文档规范

## 结论在前

学习空间的文档既是课程记录，也是学习者能力与证据的长期载体。正式学习材料按稳定主题、课程单元或项目模块组织，不按每次讨论、练习或 Agent 动作新增文件。除 `index.md` 外，每份新建或实质更新的学习文档都应使用统一五段式，并且只聚焦一个稳定的学习主题、单元或职责。每次学习先从 `学习空间/index.md` 获取导航，再按需读取课程路线、进度和相关单元；学习结束后同步更新受影响索引。

## 正文

### 文档统一结构

除 `index.md` 外，每份实质性学习文档按以下顺序组织：

1. **元信息头**：标题、版本、日期、状态（草稿 / 评审中 / 当前有效 / 已替代 / 已归档）；状态的生命周期语义见 [产物保鲜规范](./产物保鲜规范.md)。
2. **结论在前**：用 3-5 句话说明已学会什么、证据、关键误区、限制或下一步。
3. **正文**：按层级组织概念、实验、练习、反馈、验证结果和学习者自己的解释。
4. **关联引用**：引用学习空间文件时使用相对路径 Markdown 链接。
5. **变更记录**：记录重要更新的日期、版本和摘要。

### 文档粒度与索引

- 每个稳定学习主题、课程单元或项目模块使用一个目录；目录内的 `index.md` 是当前入口，`整体方案.md` 是该模块的当前权威主文档，说明学习目标、整体路径、关键结论、边界与子文档关系。
- 默认先更新 `整体方案.md`。只有内容有独立的生命周期、读者、评审方式或变更节奏时，才拆出职责明确的子文档，例如 `练习说明.md`、`项目要求.md` 或 `验收标准.md`。
- 文件名应让学习者不打开也理解内容与用途：目录上下文不足时，使用“对象 + 职责”；不要使用“讨论记录”“补充”“最终版”“最新版”或版本号作为当前文档名。
- 一份文档聚焦一个稳定学习主题、单元或职责；新的理解、练习结论和日常修订原地更新。只在出现新的稳定模块或独立职责时拆分，并从入口索引链接过去。
- 不把整门课程、所有练习和全部复盘堆在同一份无边界正文中。复杂学习通过模块目录分层；正文过长时按稳定职责拆分。
- `index.md` 只保留元信息、目录条目、一句话简介、状态和更新时间，不重复课程正文或过程细节。正式目录索引只能列当前有效或仍待处理的内容；历史版本只从 `归档/index.md` 进入。

### 按需获取与回写

1. 先读 `学习空间/index.md`，再按需读学习简报、课程路线、学习进度和当前目录的 `index.md`。
2. 只打开本次学习需要的单元、练习和复盘，不预加载整个学习空间。
3. 新建、实质更新、定稿或废弃文档后，更新父级 `index.md` 的相对链接、简介、状态和更新时间；归档材料只更新归档索引，不混入正式索引。
4. 每次学习结束时，检查索引是否能让下一次学习快速恢复上下文。
